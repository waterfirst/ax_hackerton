# 혼팀 OS

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

delegated: 공개 배포가 즉시 가능한 정적 HTML, CSS, ES modules. 상태는 브라우저 localStorage에 저장하고, 선택적 OpenRouter 연결은 사용자가 입력한 키를 현재 탭 메모리에만 유지한다.

## Users

ChatGPT, Claude, Codex, Gemini 등 여러 AI를 번갈아 쓰는 개인 창작자, 연구자, 개발자와 소규모 팀. 이들은 같은 일을 여러 AI에게 중복 지시하거나, 결정과 근거가 대화 사이에서 유실되는 문제를 겪는다.

## Product Purpose

프로젝트 목표를 검증 가능한 작업으로 나누고, 작업마다 실행자 한 명과 검증자 한 명을 지정하며, AI 결과를 다음 실행자가 읽을 수 있는 짧은 바톤으로 변환한다. 성공은 사용자가 몇 초 안에 현재 담당자, 충돌, 승인 필요사항, 다음 행동을 파악하는 것이다.

## Positioning

AI를 더 많이 호출하는 채팅 도구가 아니라, 여러 AI가 같은 일을 반복하거나 서로의 결정을 덮어쓰지 못하게 하는 협업 통제 계층이다. 단일 작업자 임대, 기준본, 완료조건, 독립 검증, 압축 바톤을 하나의 흐름으로 묶는다.

## Operating Context

사용자는 프로젝트 목표와 제약을 입력하고, 혼팀 OS가 만든 작업지시서를 원하는 AI에 전달한다. AI 결과를 다시 붙여 넣으면 서비스가 완료내용, 결정, 근거, 미해결사항을 추출해 프로젝트 장부와 다음 바톤을 갱신한다. 공모전 데모에서는 POD·전자책 출판 프로젝트를 사용한다.

## Capabilities and Constraints

- 프로젝트 목표를 역할별 작업으로 분해한다.
- 기존 작업과 의미가 겹치거나 같은 산출물을 수정하는 작업을 경고한다.
- 작업마다 실행자, 검증자, 완료조건, 상태를 기록한다.
- 한 작업에는 활성 실행자 한 명만 둔다.
- AI 결과를 바톤 형식으로 압축한다.
- 외부 게시, 이메일, 결제, 삭제, 주문은 사람 승인 대상으로 표시한다.
- 기본 데모는 계정과 서버 비밀키 없이 작동해야 한다.
- OpenRouter 연결은 선택사항이며 키를 저장하거나 전송 서버에 남기지 않는다.
- 임의 코드를 실행하거나 사용자의 로컬 파일을 직접 수정하지 않는다.

## Brand Commitments

- 제품명: 혼팀 OS
- 설명: 혼자 일하지만, 혼자 일하지 않는 방법
- 말투: 짧고 구체적인 한국어. 과장된 생산성 주장보다 확인 가능한 상태와 다음 행동을 우선한다.

## Evidence on Hand

- 실제 Claude·Codex 협업 사고에서 도출한 11개 운영 규칙.
- 단일 작업자 임대와 프로젝트별 기준본 등록부의 운영 경험.
- 실제 사례: 중복 지시로 40,521토큰을 사용하고 산출물이 없었던 작업, 상태파일 덮어쓰기로 결정이 유실된 작업. 공개 데모에는 개인정보와 회사 자료를 제거한 합성 사례만 사용한다.

## Product Principles

1. 상태를 먼저 확인하고 제안은 그다음에 한다.
2. 한 작업에는 한 명만 쓴다.
3. 완료는 자기보고가 아니라 재현 가능한 검증으로 결정한다.
4. 전체 대화가 아니라 다음 행동에 필요한 문맥만 넘긴다.
5. 되돌리기 어려운 행동은 사람이 승인한다.

## Accessibility & Inclusion

키보드만으로 주요 흐름을 완료할 수 있어야 하며, 색상 외에 텍스트와 형태로 상태를 구분한다. 모바일 화면에서 가로 스크롤 없이 사용할 수 있어야 한다.
